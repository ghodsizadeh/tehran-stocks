# اتصال دستیار هوش مصنوعی با سرور MCP

نسخهٔ ۳ `tehran-stocks` یک سرور رسمی **Model Context Protocol (`MCPServer` بر پایهٔ `mcp>=2.0`)** درون خود دارد. با اتصال این سرور به دستیارهای هوش مصنوعی مانند **Claude Desktop**، **Cursor**، **Windsurf**، **Codex** یا **Antigravity**، مدل هوش مصنوعی می‌تواند به‌جای حدس زدن اعداد قدیمی، مستقیماً داده‌های لحظه‌ای و تاریخی بورس تهران را از TSETMC بخواند و تحلیل کند.

!!! tip "ترکیب طلایی: MCP + Agent Skills"
    سرور **MCP** «ابزار دسترسی به داده» را در اختیار هوش مصنوعی می‌گذارد. اگر کنار آن [مهارت‌های عامل (Agent Skills)](skills.md) را هم نصب کنید، هوش مصنوعی قواعد خاص بورس تهران (تفاوت ریال و تومان، حجم مبنا، تعدیل قیمت، صف خرید/فروش و تقویم جلالی) را نیز به‌صورت دقیق رعایت می‌کند.

---

## دو حالت اجرای سرور MCP

| حالت | چه ابزارهایی فعال می‌شود؟ | مناسب برای چه کسی؟ |
| :--- | :--- | :--- |
| **حالت پیش‌فرض (بدون دیتابیس)** | **۱۰ ابزار زندهٔ بازار** + **۳ منبع `tsetmc://...`** | اکثر کاربران — سریع، بدون نیاز به راه‌اندازی و همیشه به‌روز |
| **حالت متصل به دیتابیس (`--db`)** | همهٔ موارد بالا + ۲ ابزار `sync_local_db` و `query_local_db` (SQL فقط‌خواندنی) | تحلیل‌های عمیق تاریخی و SQL روی انبار دادهٔ محلی (**فقط برای کلاینت‌های مورد اعتماد**) |

---

## گام ۱: پیکربندی کلاینت هوش مصنوعی (حالت بدون نصب با `uvx`)

ساده‌ترین راه، اجرای سرور از طریق `uvx` با پروتکل استاندارد `stdio` است (تمام لاگ‌ها فقط روی `stderr` نوشته می‌شوند تا جریان JSON-RPC روی `stdout` کاملاً تمیز بماند):

=== "Claude Desktop / Antigravity / عمومی"

    این بخش را در فایل تنظیمات MCP کلاینت خود (مثلاً `claude_desktop_config.json`) اضافه کنید:

    ```json
    {
      "mcpServers": {
        "tehran-stocks": {
          "command": "uvx",
          "args": ["--from", "tehran-stocks", "tse", "mcp"]
        }
      }
    }
    ```

=== "Cursor (`.cursor/mcp.json`)"

    در پوشهٔ پروژه یا مسیر سراسری Cursor فایل `.cursor/mcp.json` را بسازید:

    ```json
    {
      "mcpServers": {
        "tehran-stocks": {
          "command": "uvx",
          "args": ["--from", "tehran-stocks", "tehran-stocks-mcp"]
        }
      }
    }
    ```

=== "اگر بسته را از قبل نصب کرده‌اید"

    اگر `tehran-stocks` در محیط فعال شما نصب است، می‌توانید مستقیماً فرمان `tehran-stocks-mcp` (یا `tse mcp`) را بدون `uvx` صدا بزنید:

    ```json
    {
      "mcpServers": {
        "tehran-stocks": {
          "command": "tehran-stocks-mcp",
          "args": []
        }
      }
    }
    ```

## گام ۲: اتصال سرور MCP به پایگاه دادهٔ محلی و تنظیم پروکسی (اختیاری)

اگر می‌خواهید دستیار هوش مصنوعی بتواند پایگاه دادهٔ محلی شما را همگام‌سازی کند و روی آن پرس‌وجوی SQL فقط‌خواندنی اجرا کند، گزینهٔ `--db` (یا متغیر محیطی `TEHRAN_STOCKS_DB`) را اضافه کنید:

```json
{
  "mcpServers": {
    "tehran-stocks": {
      "command": "uvx",
      "args": [
        "--from",
        "tehran-stocks",
        "tse",
        "mcp",
        "--db",
        "/path/to/tse.sqlite"
      ],
      "env": {
        "TEHRAN_STOCKS_TIMEOUT": "30",
        "TEHRAN_STOCKS_PROXY": ""
      }
    }
  }
}
```

!!! warning "نکتهٔ امنیتی دربارهٔ `--db`"
    گزینهٔ `--db` را تنها برای کلاینت‌های مورد اعتماد فعال کنید. ابزار `query_local_db` تنها پرس‌وجوهای فقط‌خواندنی (`SELECT` / `WITH`) را می‌پذیرد و دستورات تغییردهنده (`INSERT`، `UPDATE`، `DELETE`، `DROP`) را مسدود می‌کند، اما همچنان داده‌های فایل دیتابیس محلی را برای کلاینت قابل خواندن می‌کند.

## گام ۳: اجرای سرور به‌صورت شبکه‌ای (`streamable-http`)

اگر می‌خواهید سرور MCP را روی یک پورت محلی یا داخلی (برای وب‌اپ‌ها یا کلاینت‌های ریموت) اجرا کنید، از حالت `streamable-http` استفاده کنید:

```bash
# اجرا روی آدرس محلی (پیش‌فرض: 127.0.0.1:8000)
tse mcp --transport streamable-http --host 127.0.0.1 --port 8000

# یا با اتصال به پایگاه داده و پروکسی
tse mcp --transport streamable-http --host 127.0.0.1 --port 8000 \
  --db ./tse.sqlite --timeout 30
```

| گزینهٔ خط فرمان | متغیر محیطی معادل | کاربرد |
| :--- | :--- | :--- |
| `--db` | `TEHRAN_STOCKS_DB` | مسیر فایل SQLite یا URI برای PostgreSQL / DuckDB |
| `--transport` | — | نوع ارتباط: `stdio` (پیش‌فرض) یا `streamable-http` |
| `--timeout` | `TEHRAN_STOCKS_TIMEOUT` | زمان انتظار درخواست‌های HTTP به ثانیه |
| `--proxy` | `TEHRAN_STOCKS_PROXY` | آدرس پروکسی HTTP یا SOCKS در صورت نیاز |
| `--host` / `--port` | — | آدرس و پورت سرور در حالت `streamable-http` |
| `--log-level` *(روی `tehran-stocks-mcp`)* | `TEHRAN_STOCKS_LOG_LEVEL` | سطح لاگ روی `stderr` (پیش‌فرض `INFO`) |

## سناریوهای واقعی: چه چیزهایی می‌توانید از هوش مصنوعی بپرسید؟

پس از اتصال سرور، نیازی نیست نام ابزارها را حفظ کنید؛ کافی است به زبان طبیعی فارسی بپرسید و دستیار خودکار ابزارهای مناسب را صدا می‌زند:

### سناریوی ۱: تحلیل کامل یک سهم
> **پرامپت شما:**
> «سهم **کگل** را کامل بررسی کن: آخرین قیمت و قیمت پایانی، وضعیت ورود پول حقیقی و قدرت خریدار در ۱۰ روز گذشته، آیا صف خرید یا فروش دارد و آخرین پیام ناظر و اطلاعیه‌های کدال آن چیست؟ اعداد را به تومان گزارش کن.»

**چه اتفاقی می‌افتد؟** دستیار ابزارهای `get_stock_snapshot`، `get_client_type_flow`، `get_order_book` و `get_disclosures` را صدا می‌زند و یک گزارش یکپارچه تحویل می‌دهد.

### سناریوی ۲: رصد بازار و فیلترنویسی هوشمند
> **پرامپت شما:**
> «وضعیت امروز بورس تهران و اختلاف رشد شاخص کل و هم‌وزن را بگو. بعد از کل بازار، ۱۰ نماد برتر که صف خرید ندارند ولی قدرت خریدار بالای ۱.۵ و بیشترین ورود پول حقیقی را دارند فهرست کن.»

**چه اتفاقی می‌افتد؟** دستیار منبع `tsetmc://market/overview` (یا ابزار `get_market_overview`) و ابزار `screen_market` را صدا می‌زند و در چند ثانیه فهرست فیلترشده را برمی‌گرداند.

### سناریوی ۳: بررسی حباب صندوق‌های ETF
> **پرامپت شما:**
> «قیمت فعلی صندوق **بمان** را با NAV ابطال و NAV آماری آن مقایسه کن و بگو الان چقدر حباب مثبت یا منفی دارد.»

**چه اتفاقی می‌افتد؟** دستیار با `get_fundamentals_and_events(symbol="بمان", include_etf=True)` و `get_stock_snapshot` درصد حباب را دقیق محاسبه می‌کند.

### سناریوی ۴: پرس‌وجوی تحلیلی روی تاریخچهٔ دیتابیس محلی *(با `--db`)*
> **پرامپت شما:**
> «دیتابیس محلی را برای نمادهای `فولاد`، `کگل` و `فملی` به‌روز کن و بعد با یک کوئری SQL، ۵ روزی که در سال ۱۴۰۳ بیشترین ارزش معاملات را در `فولاد` داشته‌ایم نشان بده.»

**چه اتفاقی می‌افتد؟** دستیار ابتدا `sync_local_db` و سپس `query_local_db` را با کوئری `SELECT` امن اجرا می‌کند.

## خلاصهٔ قابلیت‌های در دسترس مدل

- **۱۰ ابزار زندهٔ بازار:** جست‌وجوی نماد (`search_instruments`)، گزارش یکپارچهٔ سهم (`get_stock_snapshot`)، تاریخچهٔ تعدیل‌شده با تاریخ جلالی (`get_price_history`)، جریان پول حقیقی/حقوقی (`get_client_type_flow`)، ۵ سطر سفارش و تشخیص صف (`get_order_book`)، بنیاد/سهامداران/ETF (`get_fundamentals_and_events`)، نمای کلی بازار (`get_market_overview`)، شاخص‌ها و اثر نمادها (`get_indices`)، فیلتر کل بازار (`screen_market`)، کدال و پیام ناظر (`get_disclosures`).
- **۲ ابزار پایگاه داده (فقط با `--db`):** همگام‌سازی افزایشی (`sync_local_db`) و اجرای SQL فقط‌خواندنی (`query_local_db`).
- **۳ منبع آماده (MCP Resources):** `tsetmc://market/overview`، `tsetmc://market/sectors` و `tsetmc://instrument/{symbol}`.
